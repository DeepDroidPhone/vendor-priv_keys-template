# DeepDroid private signing keys

Place this directory at:

```text
vendor/priv/keys
```

Add only this line to `vendor/aosp/config/common.mk`:

```make
-include vendor/priv/keys/keys.mk
```

`keys.mk` is generated by `./keys.sh`, and it includes `BoardConfigPrivKeys.mk`.

## Generate

From `vendor/priv/keys`:

```bash
./keys.sh
```

The script generates the signing keys and then creates/updates the build-integration files:

```text
keys.mk
Android.bp
BUILD.bazel
```

The active DeepDroid profile is:

```text
80 PRODUCT_CERTIFICATE_OVERRIDES mappings
73 active certificate identities
76 available android_app_certificate modules
```

Three compatibility certificate modules are intentionally available even though they are not active mappings:

```text
com.android.telecom.resources.certificate.override
com.android.telecomui.certificate.override
com.android.webapp.certificate.override
```

`./keys.sh` preserves valid existing key pairs and refuses to silently replace a complete corrupt pair. Long X.509 CN values are shortened deterministically without renaming Android modules or key files.

Do not regenerate keys after publishing a build if APK/OTA/APEX/AVB continuity matters.
